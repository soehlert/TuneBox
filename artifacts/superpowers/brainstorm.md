# Brainstorm - Party Vibe Selector & Dynamic Mood Queue Generator

## Goal
Provide a interactive **Party Vibe Selector** in TuneBox that allows hosts (and optionally guests) to pick specific mood vibes (e.g. *Party, Upbeat, Chill, Energetic, Groovy, Acoustic*) and automatically generate and preseed a custom queue of matching tracks from the local SQLite music library, capped at a configurable track count.

## Constraints
- **Track Mood Sources**: Utilize existing track, album, and artist moods stored in SQLite/Redis and generated by `calculate_top_vibes`.
- **Fast Execution**: Perform vibe matching locally in SQLite (`LIKE` / JSON search or indexed mood tags) so queue generation is instant (<100ms).
- **Strict Track ID Standardization**: Use canonical internal SQLite `track_id`s upfront.
- **Queue Priority Integrity**: Vibe-seeded tracks are added as fallback/preseed tracks (`is_fallback=True`), allowing guest request tracks to automatically take priority.
- **Configurable Track Limit**: Allow selecting/configuring how many tracks to generate (default 10, configurable up to 50+).

## Known Context
- TuneBox currently supports **Preseed from Playlist** (Admin Settings), which randomly samples tracks from a chosen Plex playlist.
- TuneBox tracks display vibes via `calculate_top_vibes(play_queue)` in WebSocket updates based on track/album mood tags.
- SQLite database (`library.db`) contains pre-indexed tracks, albums, and artists. Mood tags can be queried directly from indexed metadata.

## Risks
- **Sparse Mood Data**: If certain tracks or albums do not have mood tags assigned in Plex/SQLite, filtering strictly by single niche moods could return fewer tracks than the requested count. (Mitigation: fallback to genre matching or multi-select mood OR matching any selected vibe in a multi-select set).
- **Duplicate Tracks in Queue**: Generating multiple vibe batches could attempt to re-add songs already in the queue. (Mitigation: filter against active Redis queue tracks using `is_song_in_queue`).

## Options

### Option 1: Dual Placement — Main Page Vibe Chips + Admin Settings Preseed Tab (Recommended)
- **Main Page**: Add a sleek, interactive "Room Vibe" pill/chip bar at the top of the main dashboard or queue panel. Clicking a vibe chip (e.g. "⚡ Energetic", "🎉 Party", "☕ Chill") immediately seeds/swaps upcoming fallback queue tracks with tracks matching that vibe.
- **Admin Settings**: Add a "Preseed by Vibe" tab under Admin Controls allowing admins to multi-select vibes, set a custom track count slider/input (10–50), and generate a preseeded queue.
- **Backend API**: Add `POST /api/music/vibe/seed?vibe=Party&count=10` endpoint.

### Option 2: Admin-Only Settings Modal Vibe Generator
- Add Vibe Selection dropdown/chips solely inside the Admin Settings modal under the "Preseed Queue" section.
- *Pros*: Simple UI addition in existing settings modal.
- *Cons*: Room guests or party hosts outside settings modal cannot easily tweak the room vibe on the fly.

### Option 3: Dedicated "Vibe Generator" Modal / Drawer
- Add a dedicated "Vibe Machine" modal triggered by a button in the main top navbar.
- Allows picking multiple mood tags, setting target genre/decade filters, and previewing matching tracks before adding them to the queue.

## Recommendation
**Option 1** is recommended:
1. Create backend endpoint `POST /api/music/vibe/seed` in `backend/routers/music.py` that queries SQLite for tracks matching selected mood tags, randomly shuffles them, and adds them to Redis queue (`is_fallback=True`).
2. Add a `GET /api/music/vibes` endpoint returning available mood tags across the library.
3. Integrate an interactive "Party Vibe" chip bar on the main TuneBox dashboard and in Admin Settings pre-seed controls with configurable track count (10, 20, 30, 50).

## Acceptance Criteria
- Users/Admins can view available vibes/moods across the library.
- Selecting a vibe and setting count (e.g. 15 tracks) generates a queue of matching tracks in <100ms.
- Newly seeded vibe tracks automatically populate the queue and broadcast via WebSockets to all connected clients.
- Guest requested tracks continue to take priority over vibe fallback tracks.
- Full test coverage in `backend/tests/test_queue_mutations.py`.
